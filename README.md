# relay-backend

Backend API for **Relay**, built with [Express 5](https://expressjs.com/), [Better Auth](https://www.better-auth.com/) and PostgreSQL. It runs directly on Node's native TypeScript support (no build step) and currently provides email/password authentication.

## Tech stack

| Concern        | Choice                                   |
| -------------- | ---------------------------------------- |
| Runtime        | Node.js 22+ (runs `.ts` files natively)  |
| Web framework  | Express 5                                |
| Authentication | Better Auth (email + password)           |
| Database       | PostgreSQL via `pg` connection pool      |
| Language       | TypeScript 7 (`noEmit`, erasable syntax) |
| Package manager| pnpm                                     |

```
└── src/

    ├── lib/
    │   └── auth.ts               # Better Auth instance + PostgreSQL pool
    └── routes/
        └── routes.auth.ts        # Custom /api/v1/auth router wrapping Better Auth
```

## How it works

- `src/lib/auth.ts` creates the Better Auth instance backed by a `pg` `Pool` and enables the email/password provider.
- `src/server.ts` mounts two things:
  - The raw Better Auth handler at `/api/v1/better-auth/auth/*`. This exposes every built-in Better Auth endpoint (sign-in, sign-up, session, sign-out, etc.). It is mounted **before** `express.json()` so Better Auth can parse the body itself.
  - A custom Express router at `/api/v1/auth` that calls the Better Auth server API (`auth.api.*`) and shapes the responses.
- `better-auth_migrations/` holds the SQL generated by the Better Auth CLI. Apply it to your database before starting the server.

## API

### Better Auth (built-in)

All standard Better Auth routes are available under:

```
/api/v1/better-auth/auth/*
```

See the [Better Auth docs](https://www.better-auth.com/docs) for the full list.

### Custom routes (`/api/v1/auth`)

| Method | Path              | Body                                   | Description                                                                  |
| ------ | ----------------- | -------------------------------------- | ---------------------------------------------------------------------------- |
| POST   | `/sign-up/email`  | `{ name, email, password, image? }`    | Creates a user. `name` is required. Password must be 8–128 characters.       |
| POST   | `/sign-in/email`  | `{ email, password }`                  | Signs in and forwards Better Auth's `Set-Cookie` session headers to the client. |
| GET    | `/sign-out/email` | –                                      | Placeholder, not implemented yet.                                            |

## Getting started

### Prerequisites

- Node.js 22 or newer
- pnpm 11+
- A running PostgreSQL instance

### 1. Install dependencies

```bash
pnpm install
```

### 2. Configure environment

Create a `.env` file in the project root:

```env
BETTER_AUTH_SECRET=<random-secret-at-least-32-chars>
BETTER_AUTH_URL=http://localhost:3000
```

You can generate a secret with:

```bash
openssl rand -base64 32
```

### 3. Database

The PostgreSQL connection is currently configured in `src/lib/auth.ts`:

| Setting  | Value           |
| -------- | --------------- |
| database | `postgres`      |
| user     | `postgres_user` |
| password | `pass123`       |
| port     | `5432`          |

Either create a matching database/user or change these values. Then apply the schema:

```bash
psql -U postgres_user -d postgres -f better-auth_migrations/2026-09-17T19-15-36.148Z.sql
```

If you change the Better Auth config later, regenerate the migration with:

```bash
pnpm dlx @better-auth/cli generate
```

### 4. Run the dev server

```bash
pnpm dev
```

This runs `node --env-file=.env --watch src/server.ts`, so the server reloads on file changes. It listens on **http://localhost:3000**.

### Example requests

```bash
# Sign up
curl -X POST http://localhost:3000/api/v1/auth/sign-up/email \
  -H "Content-Type: application/json" \
  -d '{"name":"Alex","email":"alex@example.com","password":"supersecret123"}'

# Sign in (stores the session cookie in cookies.txt)
curl -X POST http://localhost:3000/api/v1/auth/sign-in/email \
  -H "Content-Type: application/json" \
  -c cookies.txt \
  -d '{"email":"alex@example.com","password":"supersecret123"}'

# Get the current session via the built-in Better Auth endpoint
curl http://localhost:3000/api/v1/better-auth/auth/get-session -b cookies.txt
```
